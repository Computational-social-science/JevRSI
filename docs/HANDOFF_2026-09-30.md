## Three errors this project made, all still in the record

They are written down because the pattern is what generalises, and because a later session reading
only the conclusions would not know which numbers had been wrong on the way there.

1. **Step time, three times.** 32-65 h (divided a 3-step total by 3, charging every one-off cost to
   every step), then 25 min (read off a `freeze_base: true` run, which the real arm does not use),
   then a 107 s/step figure from a run contending with another for the card. The settled number is
   **23 s/step at `freeze_base: false`**, and the habit behind all three is reading a number off a run
   whose conditions were not the ones being asked about.

2. **The OOM, diagnosed twice — and then withdrawn entirely.** First as "evaluation lacks
   `grad_checkpointing`", then as "32 is fine, the optimiser state alone was the fault". The second
   came from a `freeze_base: true` control that **removed half the cause**, so it could only return a
   false all-clear — and a retraction built on it was wrong in the same direction as the claim it
   retracted. The third answer was the interaction: `eval_batch_size: 32` OOMs when full-parameter
   training has left the 8.88 GiB optimiser state resident, and completes when the tower is frozen.

   > **RETRACTED 2026-10-02.** There was no interaction. The OOM came from the run that shared the
   > card with a 30-step job — **the same run whose `train_seconds` this document discards three
   > paragraphs above**. One invalidated run cannot yield one number kept and another discarded, and
   > that is what the first two diagnoses were built on. Re-measured on an idle card, 32 does not
   > OOM; it occupies 94% of VRAM and takes >61 minutes against 8's 15.6, so 8 stays for headroom and
   > speed rather than for correctness. See
   > [`eval_batch_size_correction.md`](eval_batch_size_correction.md).
   >
   > "An isolation that removes the phenomenon cannot report on it" was right, and it was applied to
   > the wrong experiment: the error was never the *control's* design, it was keeping one output of a
   > run already ruled invalid.

3. **A rewrite mistaken for a reproduction.** The first version of this work expressed RSI-Jev's
   recipe as configuration for `agentjev/train.py` — reimplementing 5,166 lines of working code. Its
   own corpus converter produced 23,319 questions against their 25,859 and ordered boolean options
   `[true, false]` where their contract asserts `("false", "true")`, which inverts the probability on
   every boolean question in the corpus. Reusing their script was both less work and more correct.

## Guard rails that must stay green

Three exist, all written for the current objective:

```bash
python scripts/check_edit_guard.py            # 14/14, 4 negative controls
python scripts/check_arm0_spec.py             # 46/46, 11 negative controls
python scripts/check_synth_decontamination.py  # 12-gram overlap 0
```

**Six more guards existed before the history rewrite and are gone with it** —
`check_language`, `check_terminology`, `check_object_purity`, `check_relative_paths`,
`check_split_disjoint`, `check_document_hygiene`. They guarded the *previous* objective: retired
object names, vocabulary lineage, harness terminology, machine paths, and three-way split
disjointness. Two of their ideas are worth rebuilding against this objective and one is not:

- **Worth rebuilding** — a language guard. The previous one was written after a Chinese-language
  objective document survived a pure-text purity scan, which is a real failure mode and will recur
  the first time a draft is written in anything but English.
- **Worth rebuilding** — a path guard. `config/paths.json` exists and `paths.py` raises loudly on a
  missing location, but nothing prevents a new file from hardcoding `E:/...` and breaking the tree's
  portability.
- **Not worth rebuilding** — the retired-object vocabulary list. Its contents are the previous
  objective's, and reviving it would import that objective's vocabulary back into a repository that
  was rewritten specifically to be free of it.

The repository history was rewritten on 2026-09-30 to a single fresh root commit. A retired
objective's artefacts — including `Problem.docx`, its Chinese brief — were reachable from any
checkout of the old SHAs. **Do not merge the old history back.** The previous tree targeted
harness-first optimisation of a retired model and is not this project.
